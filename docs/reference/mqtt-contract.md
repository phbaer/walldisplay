# MQTT contract and Home Assistant entities

Reference for the panel's MQTT topics, payloads, discovery entities, screenshots, and the release and contract versions. Moved unchanged from the README section "MQTT contract"; the [README](../../README.md) remains the overview.

The firmware, blueprint, custom integration, and Python project release is `1.3.2`; MQTT contract `12`. Both synchronization paths publish retained compatibility metadata to `<base>/set/blueprint_info`:

```json
{"version":"1.3.2","contract":"12"}
```

| Purpose | Topic | Notes |
| --- | --- | --- |
| Availability | `<base>/status` | Retained `online` / `offline`. |
| Display updates | `<base>/set/...` | Matching retained `state/...` inputs also work. |
| Commands | `<base>/cmd/...` | Non-retained buttons, media, sync, configuration, OTA, screenshots, and factory reset. |
| Panel state | `<base>/state/...` | Retained canonical values and diagnostics. |

The discovered **Default Panel Widget** select offers the enabled pages in navigation order. Its value is saved in the panel and applied immediately; it is controlled through `<base>/cmd/config/default_page` and reported at `<base>/state/config/default_page`. Home Assistant's next configuration publish restores its configured startup page, so edit the synchronization configuration for a lasting change. The discovered MQTT device name includes the configured panel name in parentheses, making similarly named panels easy to identify in Home Assistant. Discovery configuration messages use retained QoS 0 to avoid filling the panel's TLS publish queue during reconnect; diagnostic device information is published after connection by the periodic device-info timer.

Contract 12 broadens `state/device.ipv6_global` to prefer IPv6 ULA addresses before global addresses and permits bracketed IPv6 hosts in `state/screenshot.url`. Topics and existing fields remain unchanged. Both synchronization paths publish release `1.3.2` / contract `12`; releases `1.3.1` (setup portal hardening) and `1.3.2` (internal firmware structure) do not change the contract.

Contract 6 adds retained `<base>/set/pages` configuration and `<base>/state/config/pages` canonical reporting. Contract 8 adds the `about` page. Contract 9 expands the ordered page layout to five slots (`page1` through `page5`):

```json
{"pages":["weather","media","about"],"default_page":"weather","titles":{"weather":"Weather","media":"Media","buttons":"Buttons","about":"About"}}
```

The payload must be shorter than 1024 bytes. Each `<base>/set/grid/N` (N = 1–6) carries retained JSON such as `{"label":"Lights","state":"on"}`; use `stateless` for action-only controls. Presses publish non-retained `press` to `<base>/cmd/gridN`. Synchronization paths ignore presses for hidden controls or a disabled buttons page. Upgrade firmware and the selected synchronization path together to release 1.0.0 / contract 9; older weather/media topics remain supported, but older peers cannot use the five-slot layout and report a compatibility mismatch.

Display data uses `set/name`, `set/weather`, `set/media`, `set/clock`, `set/date`, `set/chipN`, `set/chipN/color`, `set/buttonN/label`, and `set/buttonN/state`. `set/name` carries the human display label; the firmware derives and applies the Wi-Fi hostname and publishes both `state/name` and `state/hostname`. The label is shown smaller and muted below the clock. The header shows large, unified clock and date labels at the upper left and upper right, respectively, both with 14 px top and outer-side padding. Select 24-hour (default) or 12-hour time in either synchronization path. Its Wi-Fi, MQTT, and Home Assistant indicators form one three-section rounded status control; only its outer corners are rounded. The Home Assistant indicator turns green on the global `homeassistant/status=online` birth message and on the retained clock synchronization published every minute by either synchronization path. This panel-local heartbeat also fixes the amber state when the panel connects after Home Assistant has already started. Discovery publication is best effort: a transient MQTT disconnect during reconnect no longer aborts the firmware, and discovery is retried on the next connection. `set/media` accepts plain text or JSON, for example:

```json
{"state":"playing","title":"Track","artist":"Artist","artwork_url":"https://example.invalid/cover.jpg"}
```

Media commands are `cmd/media/previous`, `play_pause`, `next`, `power_off`, `volume_down`, `volume_up`, `volume`, and `favoriteN`. The `power_off` command is a toggle when a **Media power switch** is configured; both synchronization paths call `homeassistant.toggle` and publish its retained state through `set/media/power` as `{"configured":true,"state":"on"}`. The panel shows the power control only when `configured` is true and highlights its current state. With no configured switch, the control remains hidden. It places a horizontal blue volume rocker beside the transport controls: its generously sized transparent `−` and `+` touch ends have explicit matching outer insets and support a tap for a small adjustment or press-and-hold repeat, while its central slider publishes `cmd/media/volume` with an integer percentage from 0 to 100 and follows the `volume_level` media-state field. The favourites row uses the full width beneath the controls. The media page uses a 136 px cover-art area and a separate metadata column showing title, artist, album, source, and playback state; favourites publish retained labels and icons, and their play-media JSON targets the selected player. `walldisplay_sync` fetches the selected player's artwork with a 1 MiB download limit and a 16-megapixel decode limit, converts it to a bounded JPEG, and serves it from a random-token panel URL with a content revision; configure an internal or external Home Assistant URL reachable from the panel. Firmware TLS uses dynamic record buffers so artwork HTTPS fetches can coexist with the persistent MQTT session. Failed artwork downloads remain retryable. Newer requests and clear operations supersede old downloads; successful sources are refreshed after a 60-second cache interval on the next media update. Configuration, clock, controls, weather, and media publish independently, so slow or failed artwork cannot block control configuration. MQTT Sync remains a no-custom-code alternative and forwards its media URL directly, so its source must already be a reachable baseline JPEG.

Weather accepts text or JSON with `condition`, `temperature`, `humidity`, `pressure`, `wind_speed`, `rainfall`, `irradiance`, a `trend` of up to 25 historic temperature values, and up to three forecast entries. The current temperature uses a larger bold value; available humidity, pressure, wind, rain, and solar-irradiation readings form a vertically aligned icon-led column on the right. Humidity uses a droplet, rain uses a downpour marker, and wind uses wave marks. The `wind_unit`, `rainfall_unit`, and `irradiance_unit` fields preserve sensor units. The panel renders the last 24 hours of temperature history as a rounded background curve beneath current conditions; it never uses forecast values. Both sync paths request 24 hourly Recorder means for the optional temperature sensor (or the weather entity when no sensor is configured), then append the current value. The trend requires Recorder data and a source entity that provides long-term statistics, normally a temperature sensor with `state_class: measurement`; otherwise the curve remains hidden. Both sync paths use tomorrow through day +3 only for the forecast cards; optional temperature, humidity, pressure, wind-speed, rainfall, and irradiance sensors override their matching weather-entity attributes. Wind falls back to the standard weather `wind_speed`/`wind_speed_unit` attributes; rainfall and irradiance use matching attributes when a provider exposes them. A configured footer state entity is toggled on press; otherwise the integration emits an event and MQTT Sync runs its configured action. `cmd/wake` and any touch restore brightness, while `cmd/sync` requests a complete refresh.

The MQTT device exposes **IP Address** (IPv4), **IPv6 Address** (global), and **IPv6 Link-local Address** diagnostics. Addresses refresh every minute; missing IPv6 addresses report `unavailable`. These firmware-discovered entities, **Screenshot Token**, **Capture Screenshot**, and **Screenshot Status** are identical for the blueprint and custom integration paths. Enable screenshots in the selected synchronization path after setting the token. Press **Capture Screenshot** on the device to capture its current page. **Screenshot Status** displays `capturing`, `ready`, or `error`; its attributes include the capture name, the download URL and byte count on success, or `error` (ESP-IDF error name) and `stage` on failure. Rejected requests also publish an error, covering disabled/uninitialized capture, invalid names, and a busy queue. The download still requires the bearer token.

Contract 11 adds the non-retained `cmd/config/screenshot_token` configuration command, screenshot status discovery/error attributes, and IPv6 diagnostics. Token commands persist in NVS without rebooting, never echo the secret in state, and reject retained command deliveries. The password-mode text entity is command-only, so it does not reveal the saved token. Home Assistant sends the token through MQTT; restrict broker access and use TLS. Token settings belong to the device and are not overwritten by blueprint/integration synchronization.

The physical panel’s Home Assistant device exposes every canonical MQTT command and writable input through discovery. The custom integration explicitly links its native button/event/sensor entities to the existing MQTT-owned device after setup or discovery. It avoids creating a second integration-owned device, because Home Assistant can scope device identities to separate integration entries even when their identifiers match. On integration reload it moves existing entities, including disabled ones, before automatically removing empty legacy WallDisplay Sync devices. The MQTT device’s internal registry ID, name/area settings, and existing entity IDs/unique IDs are retained. The removed duplicate’s device ID cannot also be retained: review automations targeting that integration-only device ID. Devices with remaining entities, other integration ownership, or child devices are left untouched. If MQTT discovery is not yet available, cleanup waits and entities remain available; ambiguous MQTT matches are not consolidated. Firmware discovery must be enabled; blueprint users receive the same firmware entities. The integration still requires manual automations for action-only footer/grid events and wake-up triggers.

JSON editors are command-only and accept up to 255 characters, Home Assistant’s text-entity limit. Use the integration/blueprint configuration or Home Assistant’s MQTT publish service for longer weather/media/layout JSON (firmware limits still apply). Full received JSON remains visible in sensor attributes even when it exceeds the sensor-state length limit. Number controls preserve the other display settings, including zero values that disable dim/off timers. Payload editors publish non-retained messages; accepted configuration continues to be reported as retained canonical state. Legacy `state/...` input aliases and `cmd/reboot` share the canonical controls rather than creating duplicates. Hostname is derived from the panel name and is read-only.

Device Diagnostics includes every published device field: IPv4/IPv6, MAC, firmware and synchronization versions/contracts, hardware model, configured panel name/topic/discovery prefix, Wi-Fi SSID/BSSID/channel/RSSI, configuration flags, TLS requirement, whether a screenshot token is configured, running partition, reset reason, uptime, and current/minimum heap and PSRAM. Credentials and token contents are never returned. Screenshot and update diagnostics preserve their complete error/progress payloads as attributes; grid payloads are reported only after the panel accepts them.

The selected synchronization path remains authoritative: its next publish can restore configured names, page layouts, display settings, labels, colours, or input state after a manual device edit. Edit the integration or blueprint configuration for lasting changes. Media, footer, favourite, and grid command buttons invoke that path’s existing routing, and may operate the configured Home Assistant devices. Native Wake Panel/Sync Panel/hostname/AP entities are retained for existing automations and now share the physical device with their firmware counterparts.

**Capture Screenshot** explicitly sends the name `screenshot`, which is also the default used by `/screenshot.bmp` without a query. Older discovery configurations used Home Assistant’s default payload `PRESS`, creating a capture named `PRESS`; use `?name=PRESS` to retrieve those captures until discovery is refreshed. **Capture Screenshot** (or `cmd/screenshot`) stores a 480×480 BMP in LittleFS and publishes progress at `state/screenshot`, including a LAN URL when complete. Publish an optional alphanumeric, `_`, or `-` name as the command payload to retain a named capture; retrieve it from `http://<panel>:8080/screenshot.bmp?name=<name>` with `Authorization: Bearer <token>`. Set the password-mode **Screenshot Token** text entity on the Home Assistant MQTT device (32–64 ASCII letters/digits), provision `security.screenshot_token` in firmware YAML, or set the token in the local setup portal, and enable **Enable authenticated screenshots** in either Home Assistant synchronization path first. `cmd/page` accepts the ID of an enabled page (`weather`, `media`, `buttons`, or `about`), enabling non-touch visual checks. Requests for disabled pages are rejected. Run `SCREENSHOT_TOKEN=<token> PANEL_TOPIC=<base-topic> PANEL_HOST=<panel-ip> bash tools/capture_screenshots.sh` to publish fixed full/minimal-weather and idle/playing-media fixtures, capture each page, and download BMPs. [`tools/capture_screenshots.sh`](../../tools/capture_screenshots.sh) also accepts optional `MQTT_HOST`, `MQTT_PORT`, `MQTT_USERNAME`, `MQTT_PASSWORD`, `MQTT_TLS`, `MQTT_CAFILE`, `MQTT_CAPATH`, `OUTPUT_DIR`, `SETTLE_SECONDS`, `CAPTURE_TIMEOUT_SECONDS`, and `RUN_ID` values. `MQTT_TLS=1` uses the system CA directory unless `MQTT_CAFILE` is supplied. Screenshot support retains the LVGL-owned display handle rather than the temporary startup board structure, so captures remain valid after the startup task returns. Captures can take several seconds while the panel renders; the default per-capture timeout is 45 seconds. It requires `mosquitto_pub`, `mosquitto_sub`, `curl`, and `timeout`; failures print the last panel status messages or explain when no status was received. The HTTP endpoint requires a bearer token and returns `Cache-Control: no-store`. Repeated captures with the same name replace the previous BMP after the new file has finished writing. It retains at most four named captures and removes captures on reboot. Captures are disabled by default; the HTTP endpoint rejects every request until a token has been configured. HTTP is not encrypted: keep this endpoint on an isolated trusted LAN, or use a TLS reverse proxy. The token is never included in MQTT status URLs.

Screenshot storage uses the pinned `joltwallet/littlefs` ESP-IDF component. A completed temporary BMP is closed before LittleFS atomically renames it over the previous capture, so repeated names work without a delete-before-rename window. Both the MQTT Sync blueprint and `walldisplay_sync` integration use the same existing screenshot commands, status, authentication, and enable settings; the filesystem change adds no MQTT contract changes.

The `storage` partition keeps its existing label, legacy `spiffs` subtype, offset `0x930000`, and size `0x6D0000`. LittleFS locates it by label regardless of subtype, allowing application-only OTA without rewriting the partition table. On its first mount, blank or SPIFFS-formatted storage is automatically reformatted as LittleFS, discarding only transient screenshots. Wi-Fi, MQTT, screenshot tokens, and panel configuration stay in separate NVS partitions. Storage initializes at boot so a token configured later through Home Assistant can enable captures. Rolling back to SPIFFS firmware reformats this same partition back to SPIFFS when screenshot support initializes; upgrading again reformats it to LittleFS. Captures are already removed on reboot. This filesystem migration is included in release `1.2.1`, as explicitly selected by the maintainer. Hardware upgrade/rollback, interrupted-write, and display-response checks remain required before release; see [LittleFS acceptance](../acceptance/littlefs-storage.md).

### Screenshot preview in Home Assistant

The custom integration provides **Panel Screenshot**, an image entity on the physical MQTT device. In **Configure → Display and weather**, set `screenshot_token` to the same token configured on the panel and enable screenshots in the selected synchronization path. The preview token is stored in the integration configuration, not sent to the panel; update it there if the panel token changes. On each successful capture the integration fetches its named BMP with bearer authentication and converts it to PNG. Home Assistant serves the preview through its authenticated image proxy; the panel token is never put in the browser URL or entity attributes. Add **Panel Screenshot** to a **Picture Entity** dashboard card. Capture/error/name/stage and preview download errors are available as image-entity attributes; a failed capture keeps the last successful preview. Offline status clears the cached image until another capture is reported. Home Assistant must be able to reach the panel on port 8080. The proxy uses only addresses from `state/device`, tries private IPv4 followed by IPv6 ULA (`fc00::/7`), and never follows the advertised screenshot URL or HTTP redirects. Globally routable IPv6 and link-local IPv6 (which need a Home Assistant interface scope) are excluded from automatic authenticated previews; use a ULA prefix for IPv6-only previews. Direct downloads support bracketed global IPv6 addresses on the trusted LAN as well.

For the MQTT Sync blueprint path, install the custom integration as a passive preview companion with `screenshot_preview_only: true` and the same `panel_topic`/`screenshot_token`. Preview-only mode loads only the image platform, subscribes to device/status/capture messages, and publishes no synchronization, commands, or update checks. Keep the blueprint as the sole synchronization path and enable screenshots there. The blueprint itself cannot proxy authenticated HTTP images; this intentional delivery difference does not remove any blueprint capability. The complete integration-editor example includes both preview settings. Enabling preview-only mode on an existing full integration entry unloads its active synchronization and other entity platforms; disable it again only after disabling the blueprint.
